# Quiz - IAM Advanced

1. You have strong regulatory requirements to only allow fully internally audited AWS services in production. You still want to allow your teams to experiment in a development environment while services are being audited. How can you best set this up?

- Create AWS org and create two OUs [prod/dev], then apply an SCP on the Prod OU

2. You are managing the AWS account for your company, and you want to give one of the developers access to read files from an S3 bucket. You have updated the bucket policy to this, but he still can't access the files in the bucket. What is the problem?

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowsRead",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::123456789012:user/Dave"
      },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::static-files-bucket-xxx"
    }
  ]
}
```

- You should change the resource to `arn:aws:s3:::static-files-xxx/*` because this is an object-level permission

3. You have 5 AWS Accounts that you manage using AWS Organizations. You want to restrict access to certain AWS services in each account. How should you do that?

- Using AWS Organizations SCP [service control policies]
  - central, preventive permission guardrails across multiple AWS accounts inside an AWS organization
  - account-wide service restrictions
    - SCP defines the max available permission for every IAM user and role
  - centralized governance
    - instead of logging into each of the 5 accounts to config IAM restrictions, you attach a single SCP to the org root or OU [organization unit]
    - thus, automatically enforcing the rule accross all target accounts

- why not?
  - using IAM roles
    - grant permissions within a single account
    - no organization-wide permission across N accounts
    - local account admins can create new, or modify existing, roles to by pass restrictions
  - using AWS config
    - detective compliance monitoring
    - not preventive
    - it doesn't prevent users from accessing or provisioning restricted AWS services

> SCPs never grante permission on their own, IAM policies must still allow the actions
