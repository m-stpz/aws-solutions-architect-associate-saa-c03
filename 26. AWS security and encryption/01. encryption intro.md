# Encryption intro

## Encryption in flight [TLS / SSL]: protecting moving data

- Data is encrypted before being sent and decrypted after being received
  - protects data while it travels over a network
- TLS certificates help with encryption [HTTP]
- Encryption avoids MITM [man in the middle attack]

```
    username: admin                             username: admin
    password: secret        <message-encrypted> password: secret
client ---> TLS encryption | ----------------> | TLS decryption ----> server
```

## Encryption at rest: protecting stored data

- Protects data while setting somewhere
- Even if someone gets access to the storage, the data is encrypted
  - raw bytes are unreadable without the key

- Data is encrypted after being received by the server
- Data is decrypted before being sent
- Stored in an encrypted form thanks to a key
- Encryption/decryption keys are managed somewhere, and the server must have access to it

### Encryption rules

- S3: default encryption is enabled automatically on all buckets using SSE-S3
  - upgrade to SSE-KMS when you need cloudtrail audit logs
  - SSE-C when the customer manages keys on-prem and passes them with every API call

- EBS & RDS: encrypting EBS volume or RDS db encrypts the storage, backupds, read replicas and snashopts
  - you can't directly encrypt an existing unencrypted EBS volume/RDS instance in place
  - you must tak a snapshot, copy it with encryption enabledm and restore a new encrypted volume/db from that encrypted snapshot

- Dynamodb: always encrypted at rest by default [can't be turned off]
  - uses AWS-owned keys, AWS-managed keys or a KMS CMK

## Client-side and envelope encryption [Protecting data before AWS sees it]

- Client-side encryption: application encrypts data locally before sending it over the network to AWS
  - AWS doesn't have access to the plaintext data or unencrypted keys
  - zero-trust or regulatory requirements

- Data is encrypted by the client and never decrypted by the server
- Server shouldn't be able to decrypt the data
