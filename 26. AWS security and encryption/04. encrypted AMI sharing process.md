# Encrypted AMI sharing process

- Sharing an encrypted AMI across AWS accounts works like sending a locked safe to a neighbor

1. hand over the safe [AMI/snapshot]
2. and the key [KMS key]
3. then they can open it

Step by step

1. Lock the AMI in account A
   - create an AMI whose underlying EBS snapshot using a CMK [customer managed key] in AWS KMS
     - you can't share AMIs encrypted with the default AWS-managed key

2. Share the safe [launch permission]
   - account A modifies the AMI's launch permissions to explicitly allow account B's AWS account ID to see and launch it

3. Share the key [KMS key policy]
   - account A updates its KMS key policy to grant account B permission to use that specific encryption key

4. Authorize the build in Account b [IAM policy]
   - inside B account, an admin attaches an IAM policy to the user/role launching the instance, allowing them to call KMS actions on Account A's key

## Important concepts

- 4 universal AWS rules that apply to S3, EBS, RD, secrets manager and KMS

- "Two-key" cross-account rule [identity + resource]
  - same account access: requires explicit `Allow` in either the IAM policy OR the resource policy
  - cross-account access: strictly requires an explicit `Allow` on BOTH sides
    - the resource owner: account A's permission + KMS key policy
    - AND the caller: account B's IAM policy

- AWS-managed keys can't be shared
  - default AWS-managed KMS keys have locked key policies that you can't edit
  - whenever a scenario requires cross-account sharing of encrypted resources [AMIs, EBS/RDS snapshots, S3 objects], ALWAYS you need a CMK
