# KMS [Key management service] Overview

- Anytime we hear the term encryption for an AWS service, it's most likely KMS
- AWS manages encryption key for us
- Fully integrated with IAM for authorization
- Able to audit KMS key usage using CloudTrail
- Integrates with most AWS services [EBS, S3, RDS, SSM...]
- Never store your secrets in plaintext, especially in your code
  - KMS key encryption also available through API calls [SDK, CLI]
  - Encrypted secrets can be stored in the code / environment variables

- KMS keys are scoped per region

## KMS Key types

- Symmetric [AES-256 keys]
  - single encryption key for both encrypt and decrypt
  - AWS services integrated with KMS use symmetric keys
  - You never get access to the KMS key unencrypted [must call KMS API to use]
- Asymmetric [RSA & ECC key pairs]
  - public [encrypt] and private [decrypt] key pairs
  - used for encrypt/decrypt, or sign/verify operations
  - public key is downloadble, but you can't access the private key unencrypted
  - use case: encryption outside of AWS [users who can't call the KMS API]

## KMS Keys

- AWS owned: SSE-S3, SSE-SQS, SSE-DDB
  - free
  - default
- AWS managed: aws/<service-name>
  - free
- Customer managed keys:
  - created in KMS: $1/mo
  - imported: $1/mo
  - `+` pay for API calls to KMS [$0.03 / 10k calls]

- Automatic key rotation
  - AWS-managed KMS key: automatic every 1 year
  - customer-managed KMS key: must be enabled
    - automatic and on-demand
  - imported: only manual rotation possible, using an alias

## Copying snapshots across regions

- AWS KMS keys are region-specifc
  - we can't use the same region to encrypt/decrypt storage in a different region
  - a key that works in London doesn't work in São Paulo

1. Take a snapshot of the volume
   - if volume is encrypted, the snapshot will also
     - You can't encrypt an existing unencrypted EBS volume in place
     - to encrypt it, you need:
       - take a snapshot
       - copy the snapshot while enabling encryption with a KMS key
       - restore the new EBS volume from the copied snapshot
   - snapshot inherits the exac same encryption as the volume

2. Copying and re-encryption
   - on cross-region snapshot copy, AWS decrypts the data using key A
   - transfers the data securely over encrypted TLS channels across AWS infra
   - re-encrypts it using a new key [Key B]

3. Restoring the new volume
   - once the copied snapshot lands in the new region, any new EBS volume you restore from that snapshot is automatically encrypted

```
region eu-west-2                                region-ap-southeast-2
EBS volume                                          EBS volume
    - encrypted with KMS                            - encrypted with KMS
    - KMS key A                                     - KMS key B
        |                                               |
EBS snapshot                                        EBS snapshot
    - encrypted with KMS                            - encrypted with KMS
    - KMS key A                                     - KMS key B
        |                                               |
        --------- [KMS ReEncrypt with KMS key B]--------

```

## KMS Multi-region keys

- Identitical KMS keys in different AWS regions that can be used interchangeably
- Multi-region keys have the same key ID, key material, automatic rotation
- Encrypt in one region and decrypt in other regions
- No need to re-encrypt or making cross-region API calls
- KMS multi-region aren't global [primary + replicas]
- Each multi-region is managed independently
- Use cases:
  - global client-side encryption
  - encryption on global dynamodb, global aurora
